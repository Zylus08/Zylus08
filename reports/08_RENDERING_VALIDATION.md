# Rendering and functional validation

Local browser preview uses Python-Markdown and GitHub-like image wrapping, content width, typography and light/dark colors. It does not emulate GitHub's sanitizer or Camo proxy; live rendering is checked separately when the branch is available.

Executed matrix: viewports 1100, 850, 600 and 375 px, both themes. All eight loaded every image and showed no horizontal document overflow. At narrow widths the hero, quant plate, skyline and research plate use recomposed picture sources. Intrinsic-width module images wrap into a single column. Browser text-bounds inspection found no clipped text in the hero variants, four flagship posters, longest research name, four technology panels, both telemetry panels, both skyline variants, quant/research variants and footer.

Visual inspection: full desktop dark and mobile light screenshots reviewed. The original wide skyline clipped its first corner; the projection origin/spacing was corrected before final capture. Windows default text decoding initially corrupted bullet glyphs in project highlights; explicit UTF-8 reads corrected it. These were observed and repaired, not waived. Small metadata labels are supplementary; core identity and project descriptions have text alternatives and ordinary Markdown context.

Initial test run: 13/16 passed; three atomic-file tests hit Windows virtual-temp WinError 650. Tests were moved to workspace-volume temporary directories, retaining the real atomic replacement operation. All 16 then passed. Tests cover live-snapshot schema, malformed/missing dates, private metadata, missing counts, changed HTML, mocked 403/429/offline behavior, no-change commits, last-good preservation, streak boundaries, valid all-zero calendars, deterministic rendering, bounded Lorenz integration and REST pagination. Mocked failure cases are not live service tests.

PNG evidence is in `screenshots/`; concept PNGs in `concepts/`. Full live integration and final validation outputs are summarized in the final release report. Structural SVG/XML checks cannot prove aesthetic quality; the browser captures and human-readable review supplement them.

## Live GitHub rendering

The pushed review branch was loaded on github.com in the actual repository README renderer. Browser color-scheme emulation selected GitHub's native light/dark themes without injecting layout CSS. All 32 README images loaded, four picture elements survived sanitization, and mobile sources were selected at 600 and 375 px. No article overflow was observed in any of eight theme/viewport combinations. GitHub's repository sidebars narrow the article to 643/474/487/294 px at the tested viewports; this differs from the profile page's surrounding chrome. Full-page GitHub screenshots and separate mobile viewport captures are included. Production profile rendering cannot be captured without merging, which remains explicitly unapproved.

All 54 SVG files were opened in the browser. Final text checks use actual glyph ascent/descent for collision detection: raw font layout boxes overestimate heavy display lettering and initially flagged false collisions despite separated visible glyphs. Final glyph-bounds checks reported zero clipping and zero text overlaps. `visual-results.json` and `github-render-results.json` record executed outcomes. Manual inspection included the full local desktop/mobile layouts, individual components, before/after comparison and live mobile viewport.

Live captures were repeated with fresh navigation at each viewport and full-page screenshots. This avoids locator-screenshot cropping and sticky-header artifacts observed in the first live captures. The supplementary mobile viewport captures show actual browser text wrapping. The replaced initial crops are not used as final evidence.

The authenticated Actions refresh succeeded, including data collection, staged rendering, validation and a normal generated commit. Linux Actions also passed the 16-test suite and byte-for-byte regeneration check. A direct local public REST/calendar integration succeeded independently of mocks. Main runtime assets occupy 639,789 bytes including icon licensing/manifest; SVG content is 634,586 bytes. Text colors on panel background have contrast ratios from 6.98:1 to 16.29:1. The secret-pattern scan found no matches; its limited scope is documented in `audit-results.json`.
